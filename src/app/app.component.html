How this website works

Load a curated export, run QC-01 to QC-40, then export the report for the data provider. Errors reject the file. Warnings are corrected or explained in the submission note.

  1. Export one CSV per table subject, event, lesion, specimen, treatment, questionnaire, annotation, image. Name each file <dataset>_<table>_<YYYYMMDD>.csv.
  2. Load it here Paste a single CSV or a JSON map of those file names to CSV text. Nothing is uploaded.
  3. Run the gate The active preset is Common codification v2.0: 310 variables, 67 value sets, 40 rules.
  4. Read errors and warnings apart Fix every error. A warning does not fail the gate; it still needs a correction or a note.

Six rules on every export

  • One nameThe column is the catalogue variable, not the local field name.
  • One unitThe unit sits in the name. The cell is only the number.
  • Coded valuesA code is from that variable’s value set, or a data-absent reason.
  • Missing valuesSay why, with a data-absent reason. Do not use 999, NA, NULL, Blank, or ND.
  • Day offsetsCalendar dates stay with the provider. The export has days from the index date.
  • No direct identifiersNo name, national ID, email, phone, address, record number, or date of birth.

The gate checks the curated CSV. It does not review mapping workbook rows or partner issue replies. A column that this package does not contain is marked N/A, not as a failure.

Eight tables, one row per thing

  • subjectOne person. Key: subject_id.
  • eventOne test or visit. Key: subject_id + event_id. Every row has event_type and day_from_index.
  • lesionOne lesion. Key: subject_id + event_id + lesion_id.
  • specimenOne specimen. Key: subject_id + specimen_id.
  • treatmentOne treatment line. Key: subject_id + treatment_id.
  • questionnaireOne administration. Key: subject_id + questionnaire_id.
  • annotationOne video mark. Key: subject_id + event_id + annotation_id.
  • imageOne image. Key: image_id. subject_id is still required on the row.

Other presets

FHIR laboratory resources, SHIELD study packages, and an Excel field catalogue use the same gate screen. They are separate configs. An Excel dictionary is audited, then adopted, then checked against a CSV extract.

  1. Audit. Upload the .xlsx as the dataset, or use Audit sample dictionary. FAIL means a blocking defect.
  2. Adopt. Use as validation config. Categories become tables; trimmed field names become headers.
  3. Check the extract. Paste or upload CSV / a JSON map of table name to CSV text. Headers must match the dictionary.

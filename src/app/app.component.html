Data Curation Checker

Validation of FHIR Observation and DiagnosticReport resources with laboratory medicine checks, critical value detection, workflow and structural rules. Supports JSON Bundles, arrays, NDJSON, and single resources.

Data source

Supported file formats

  • JSON Bundle: FHIR Bundle with Observation and/or DiagnosticReport in entry[].resource
  • JSON Array: Array of Observation and/or DiagnosticReport resources
  • Single JSON: Single Observation {resourceType: "Observation", ...} or DiagnosticReport {resourceType: "DiagnosticReport", ...}
  • NDJSON: Newline-delimited JSON (one resource per line)
  • File extensions: .json, .ndjson, .txt (max 10MB)
Example formats
Single Observation: 
{
  "resourceType": "Observation",
  "status": "final",
  "code": {
    "coding": [{
      "system": "http://loinc.org",
      "code": "2339-0",
      "display": "Glucose [Mass/volume] in Blood"
    }]
  },
  "valueQuantity": {
    "value": 95,
    "unit": "mg/dL",
    "system": "http://unitsofmeasure.org"
  }
}
JSON Array: 
[{
  "resourceType": "Observation",
  ...
},
{
  "resourceType": "Observation",
  ...
}]
FHIR Bundle: 
{
  "resourceType": "Bundle",
  "type": "collection",
  "entry": [{
    "resource": {
      "resourceType": "Observation",
      ...
    }
  }, {
    "resource": {
      "resourceType": "DiagnosticReport",
      "status": "final",
      "code": { "coding": [{ "system": "http://loinc.org", "code": "58410-2" }] },
      "result": [{ "reference": "Observation/obs-1" }]
    }
  }]
}

What gets validated?

Observation: Required fields (status, code), value vs dataAbsentReason, structure, CodeableConcepts, references, dates, URLs
DiagnosticReport: Status, code, category, subject, effective/issued, performer, result (Observation references), specimen, references
Laboratory (Observation): Common parameters (LOINC), UCUM units, reference ranges, critical value detection, specimen and method
Workflow & Structure: Bundle validation, panel/hasMember, timing, performers, resource relationships

Professional-grade validation of FHIR Observation resources with comprehensive laboratory medicine checks. Validates 144+ laboratory parameters with critical value detection, workflow validation, and structural integrity checks. Supports JSON Bundles, arrays, NDJSON, and single resources.

Data source

Supported file formats

  • JSON Bundle: FHIR Bundle with Observation resources in entry[].resource (recommended for multiple observations)
  • JSON Array: Array of Observation resources [{...}, {...}] (simple format for multiple observations)
  • Single JSON: Single Observation resource {resourceType: "Observation", ...} (for single observation validation)
  • NDJSON: Newline-delimited JSON (one Observation per line) - efficient for large datasets
  • File extensions: .json, .ndjson, .txt (or any text file containing valid JSON)
  • File size limit: Maximum 10MB per file

What gets validated?

Core FHIR Rules: Required fields (status, code), data types, constraints, invariants, resource structure
Laboratory-Specific: LOINC code validation, UCUM unit compliance, reference range consistency, specimen type matching
Parameter Validation: 144+ laboratory parameters with typical ranges, critical value detection, unit conversion (mg/dL ↔ mmol/L, etc.)
Critical Values: Automatic detection of life-threatening results with immediate error flagging (e.g., critical potassium, troponin, glucose)
Workflow: Status progression validation, timing relationships (issued vs effective), panel structure (organizer, hasMember), reflex tests
Quality Checks: Specimen types, methods (SNOMED CT), performers (Organization/PractitionerRole), devices, interpretations, fasting requirements
Structure & Relationships: Bundle validation, resource relationships, reference integrity, duplicate ID detection, external reference warnings
